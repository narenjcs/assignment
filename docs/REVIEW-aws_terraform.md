# Review: `reference/aws_terraform/` (2026-09-23)

Reviewer: Nari (Fable). Source: generated by Naren with an AWS coding agent. Decision: **reference only; DocIntel continues on CDK + AgentCore + real MCP.**

## Misses against the brief
1. Uses classic **Bedrock Agents** (`aws_bedrockagent_agent`), not **Bedrock AgentCore** (Runtime/Gateway) as the brief requires.
2. Neither "MCP server" speaks MCP (custom `{tool,input}` JSON over Lambda invoke / FastAPI). No JSON-RPC, tool discovery, or streamable HTTP.
3. Async path only; no synchronous mode and no streaming to the browser (chat buffers the Bedrock stream, API Gateway HTTP API cannot stream).
4. The Databricks "LangGraph agent" is one LLM call with no tool/MCP calls.

## Runtime breaks
- Base model id `anthropic.claude-sonnet-4-20250514-v1:0` needs an inference profile; Anthropic models are also gated in this account.
- Action group uses an OpenAPI schema but the Lambda parses/returns the *function-details* event shape; no resource policy for `bedrock.amazonaws.com` to invoke the Lambda.
- No `aws_lambda_permission` for API Gateway → 500s; CORS headers duplicated (API config + handler).
- Job id is created in the S3 trigger and never returned; UI polls a non-existent `/status/latest` route; no `package.json`/`index.html`/`App.css`.
- Databricks App code uses `SparkSession`, `dbutils`, FUSE `/Volumes` writes, PyMuPDF, MLflow, deprecated `langchain-community`, 2024 pins; Terraform points at a Model Serving URL while the app is a Databricks App.
- Static site has no bucket policy (403) and no CloudFront; deploy script is not re-runnable (`create-agent-alias`).

## Security / quality
- Static AWS access keys in Databricks + Databricks PAT in AWS; one shared Lambda role with `lambda:InvokeFunction` and Bedrock on `*`; hard-coded account/region/placeholders; no DynamoDB index; inconsistent result contract (raw text vs structured); no tests, no validation, bare `except`, `print`.

## Harvested into DocIntel
- `save_job_result` also writes `results/{jobId}/result.json` to the uploads bucket and stores `resultS3Key` on the job (uses both S3 and DynamoDB for results, R9).
- UC table gains `source_s3_key` and `char_count` columns plus Change Data Feed enabled.
- Terraform remains a viable IaC alternative (`aws_bedrockagentcore_agent_runtime` with zip deploy, `_gateway`, `_gateway_target` exist); state bucket `terraform-state-techniumlabs` if ever needed.
